# 业务资源 SSE

列表、详情、选择器和统计通过对应的 `/stream` 路由读取。连接返回 `ready` 和初始 `snapshot`，后续快照直接写入 TanStack Query 缓存。旧业务 JSON GET 路由和收到通知后重新 GET 的前端监视器已移除。鉴权、健康检查、下载和节点协议仍使用各自必要接口。

## 事件与读取边界

- `live_resource` 按租户、资源类别与资源 ID 分发已提交的变更。关系变更同时通知实际受影响的关联资源。
- 订阅先于首次读取建立，容量有限的唤醒通道仅负责唤醒；待处理变更由 mailbox 保存和合并，避免拥塞丢失最终状态。
- 节点心跳中的指标使用 `node-runtime` 补丁，源站状态使用 `origin-runtime` 补丁。revision 和时间水位阻止旧补丁覆盖新快照。
- 每 15 秒的 SSE `heartbeat` 不读取业务资源；会话校验仍有独立安全检查。节点保活不触发配置、任务或其他资源重读。
- 每次快照读取使用独立、有限生命周期的读取上下文，避免请求 arena 随长连接持续增长。

## 服务端进程内快照缓存

- 列表、详情、选项、任务历史和网站统计共用 `live_resource` 快照读取。缓存键由租户、资源类别、资源 ID、投影名称及经过校验的筛选和分页参数构成，使用带类型和长度的编码；URL 参数顺序、数值格式不影响共享，列表与详情等不同响应不会混用。
- 同一键同时最多执行一次读取，其他订阅等待同一个结果。有效快照直接复用；跨 worker 只传递拥有独立内存的 JSON 字节，不共享请求 DTO 或数据库会话。
- 已提交的业务变更先按租户、资源、ID 及已有关系投影失效，再唤醒订阅。列表的筛选归属和分页可能变化，因此同资源列表一起失效；无关租户和无关详情保留。后台补建任务、历史记录清理也发布失效通知。每次业务失效提升版本，期间完成的旧查询不能写入缓存或分发。
- 节点与源站运行态使用独立补丁代际，使缓存过期且禁止过期查询重新入缓存，但不因密集心跳反复取消基线查询。每次读取固定补丁水位，晚加入及再次读取的连接不能接受早于该水位的查询；后续补丁在基线之后发送，由现有 revision/时间校验保证最终状态。
- 默认最多 1,024 个活跃订阅组合、8,192 个订阅、128 次并发快照读取；缓存 JSON 总量 32 MiB、单项 4 MiB，键最长 4,096 字节。达到字节预算时淘汰最久未使用快照，超大结果仅向本次等待者分发而不驻留缓存。组数、订阅数或并发额度不足时返回可重试错误，避免无限积累。
- 最后一个订阅退出立即删除该键和缓存字节；在途查询仅保留完成所需的数据，完成后不能复活已删除条目。未取消的订阅仍可使用共享读取。重复响应比较使用弱引用，不阻止缓存淘汰。
- 快照有 15 秒惰性有效期，供使用 `NOW()` 的时间窗口投影在后续读取时更新；到期和 SSE heartbeat 本身不会触发业务查询。错误结果不驻留。日志尾流带有各自游标，继续按游标增量读取。
- 登录、会话续期及 SSE 周期会话校验保持数据库读取，退出与封禁不依赖资源缓存失效。本缓存只协调一个服务进程；多实例的资源失效通知尚未实现，也未新增 Redis 缓存。

## 前端生命周期

同一 URL 的活跃查询共享连接；参数变化建立对应筛选与分页订阅，卸载关闭无观察者的连接。重连重新取得快照；手动刷新显式重建当前订阅。`resource-error` 显示资源错误，`session-expired` 触发会话恢复或退出；旧会话异步结果不能覆盖新登录状态。
